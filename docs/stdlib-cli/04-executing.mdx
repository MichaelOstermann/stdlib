```ts
const root = CLI.command()

// Ship the default opinionated implementation,
// `name` is what people type to run it, used in error messages:
await CLI.run(root, { name: "miko" })

// Manually execute the command, get the result back
// and for example print to stdout/stderr yourself:
const execution = await CLI.exec(root, { name: "miko" })
execution.result
```

## Resolving

In case you need to build your own `run` or `exec`, some building blocks are exposed:

```ts
// Minor processing of argv, for example does it contain
// --help, what are the flags, what is the command path, etc.:
const argv = CLI.resolve.argv()
const argv = CLI.resolve.argv(process.argv.slice(2))
CLI.run(root, { argv, name: "miko" })
CLI.exec(root, { argv, name: "miko" })

// Try to find the command that matches argv:
const command = CLI.resolve.command(root, argv.path)

// Try to find the closest matching command,
// useful for "Did you mean?" messages:
const command = CLI.commands.nearest(root, argv.path)

// Get a flat list of commands that have actions,
// this is used internally in combination with
// CLI.prompt.command(commands) to let users pick one:
const commands = CLI.commands.pickable(command)
// Filter out unwanted command trees, for example RPC commands:
const commands = CLI.commands.pickable(command, (command) => command !== rpc)

// Resolve the options of a command:
const foo = CLI.boolean()
const result = await CLI.resolve.options({ foo }, argv.flags)
const result = await CLI.resolve.option("foo", foo, argv.flags)
```
